# Keep / Cleanup decision contract

This document replaces historical maintainer-session notes with the current
public contract. See [release validation](release-validation.md) for executed checks.

The shared policy first asks whether an email has current unresolved importance,
then whether it has durable personal-record value. Transient or replaceable
content can be a cleanup candidate. A sender or broad message category alone does
not establish retention value. The full policy is in `app/services.py`.

Laya returns KEEP, CLEANUP or NEEDS_REVIEW with native probabilities and entropy
confidence. Close competing decisions, insufficient context and contradictory
value evidence retain review. Its question allowance is 1,024 tokens and total
sequence allowance 1,536. Reasons summarize selected criteria; they are not
free-form explanations generated by Laya.

Winnow uses a single binary KEEP/CLEANUP question. Cleanup probability strictly
above 0.60 routes to candidates, strictly below 0.20 to Keep; both boundaries and
the intermediate band go to local Qwen. A failure or unresolved result remains
reviewable. Neither model's confidence is a calibrated correctness probability.

Both branches classify independent copies of the same fetched snapshot, preserve
original model judgments, and can request local Qwen review. Comparisons do not
merge decisions or establish accuracy. Opted-in correction memory influences
eligible review; weak or conflicting matches do not authorize deletion.

Exact subject overrides are configured explicitly in `cleanup_subject_preferences`
in `config.json`, empty by default. They affect recommendations, not mailbox
writes. Public defaults contain no personal sender/subject override. Synthetic
regressions cover exact matching, Starred protection, default behavior, original
score preservation, and absence of automatic Gmail mutation.

Selection, expiring exact-count confirmation, account binding, current-label
checks and Starred protection govern every Trash action. The Important label
alone is not protected by the current policy. Model evaluation on a broad labeled
real-mailbox dataset remains unestablished; regression and smoke tests verify
contracts and runtime behavior, not classification accuracy.
